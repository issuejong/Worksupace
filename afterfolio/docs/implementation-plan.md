# Young Planner 구현 계획

작성일: 2026년 11월 3일

현재 작업 폴더의 `afterfolio/` 안에 독립적인 Next.js 프로젝트를 구성한다. 상위 폴더가 기존 Git 저장소이므로 중첩 Git 저장소를 만들지 않는다. 기존 `umc-night/`와 그 안의 변경 사항은 작업 범위에서 제외한다.

현재는 계획 문서만 생성했다. 앱 초기화, 패키지 설치, 실제 AI 호출, 배포는 아직 실행하지 않았다.

## 목표와 1차 범위

첨부한 가상 부부 한 사례를 바탕으로 2026년 11월~2060년 12월의 410개월 현금흐름을 계산한다. 일곱 기본 시나리오와 사용자 변경안을 비교하고, 입력 화면과 AI 질문이 같은 계산 엔진을 사용하도록 만든다.

완료할 사용자 흐름:

1. 접속하면 기본 사례와 설계 결과를 확인한다.
2. 생활비·재취업·대출·추납·주택연금 조건을 변경한다.
3. 설계 전, 기획 채택안, 사용자 변경안의 지표·그래프를 비교한다.
4. AI에게 질문해 조건을 변경하거나 결과·근거를 설명받는다.
5. 시나리오, 월별 결과, 그래프, AI 검증 기록을 내려받는다.
6. PC·모바일에서 배포된 웹 앱을 사용한다.

1차 범위에는 회원가입, 실제 계좌 연결, 여러 고객을 관리하는 CRM, 임의 고객의 모든 국민연금 이력을 처리하는 범용 엔진, 실시간 법령 수집, 투자 종목 추천, 자동 최적화를 포함하지 않는다. 주택연금은 선택한 가입 시점을 비교하며 모든 시점을 탐색한 최적해라고 표현하지 않는다. 상속재산 비교는 주택연금 채무까지 검증한 경우에만 제공한다.

## 기술 구성

| 영역 | 선택 | 역할 |
| --- | --- | --- |
| 앱·서버 | Next.js App Router, React, TypeScript | 화면·API를 한 프로젝트에서 관리 |
| UI | Tailwind CSS, shadcn/ui | 입력, 카드, 표, 탭, 대화 화면 |
| 차트 | Recharts | 금융자산 추이와 연도별 수입·지출 |
| 계산 | 순수 TypeScript 함수, decimal.js | UI·AI와 독립된 월별 재무 계산 |
| 스키마 | Zod | 입력, 저장 파일, AI 도구 인자 검증 |
| AI | OpenAI 공식 JavaScript SDK, Responses API | 함수 호출과 계산 결과 설명 |
| 테스트 | Vitest | 계산·경계 월·시나리오·AI 인자 검증 |
| 초기 저장 | localStorage, JSON·CSV 내보내기 | 브라우저 보관과 파일 공유 |
| 배포 | Vercel | Next.js 앱과 서버 API 실행 |

초기화 시 지원되는 안정 버전과 호환성을 확인하고 lockfile로 고정한다. 모델 ID는 환경변수 `OPENAI_MODEL`로 선택한다. 같은 한국어 질문 세트로 조건 해석·근거 설명·응답시간·비용을 평가한 뒤 모델을 확정한다.

초기에는 공유 DB 없이 구현한다. 브라우저 저장은 기기 간 동기화가 되지 않으므로 JSON 파일로 옮긴다. 공동 서버 저장이 필요해지면 별도 범위로 추가한다.

## 데이터 계약

| 데이터 | 포함할 항목 |
| --- | --- |
| CustomerProfile | 생년월, 퇴직·근로 종료월, 급여, 초기 금융자산, 주택, 대출, 기존 연금 가입 이력 |
| Assumptions | 물가·임금·운용수익률, 생활비, 비상자금 기준, 분석 종료월 |
| ScenarioConfig | 구직급여·재취업·대출 상환·추납·주택연금 선택과 시작·종료월 |
| MonthlyResult | 소득별 수입, 항목별 지출, 대출 잔액, 운용수익, 금융자산, 물가 조정 금액, 부족액 |
| SimulationResult | 월별 결과, 연별 집계, 최초 부족월, 최저 자산, 비상자금 판정, 기말 자산 |
| SourceRecord | 출처 ID, 기관, URL, 기준일, 확인일, 관련 입력·산식, 확인 상태 |
| AuditRecord | 질문, 제안·적용한 변경, 모델·프롬프트·계산 버전, 결과 ID, 답변, 참조 출처 ID |

내부 금액 단위는 원으로 통일하고 Decimal의 JSON 입출력은 십진 문자열을 사용한다. 만원 표시는 화면에서 변환한다. 비율 단위·월 번호 변환·반올림 규칙을 한 곳에 정의한다. 날짜는 월 단위의 `YYYY-MM`을 기본으로 사용해 시간대 때문에 지급월이 달라지지 않도록 한다.

고객 설정값, 공식 확인 사실, 미확인 수치를 같은 ‘확정’ 상태로 관리하지 않는다. 입력·산식·출처·결과에 버전을 붙여 변경 후 결과와 이전 AI 설명이 섞이지 않게 한다.

## 기본 시나리오

| ID | 이름 | 적용 조건 |
| --- | --- | --- |
| S0 | 설계 전 | 현재 계획, 정기 대출 상환, 추가 대책 없음 |
| S1 | 재취업 | S0＋구직급여＋재취업 |
| S2 | 대출 상환 | S1＋은퇴 시 주택담보대출 전액 상환 |
| S3 | 추납 적용 | S2＋아내 119개월 추납 |
| S4 | 2031년 주택연금 | S3＋2031년 2월 가입, 기획 채택안 |
| S5 | 2027년 주택연금 | S3＋2027년 2월 가입 |
| S6 | 2035년 주택연금 | S3＋2035년 2월 가입 |

S4~S6는 S3에서 분기한다. S5·S6를 S4에 더하지 않는다. 사용자 변경안은 기준 시나리오 ID와 변경값을 보관하고 기본안을 덮어쓰지 않는다.

초기 화면은 S0·S4·사용자 변경안을 비교한다. 상세 비교에서 다른 기본안을 선택할 수 있다. 대책만의 효과를 비교할 때는 물가·수익률 등 다른 조건을 동일하게 둔다. 원본의 서로 다른 설계 전후 수익률을 재현하는 검증과 조건을 맞춘 대책 비교는 구분한다.

## 단계별 구현과 완료 기준

### 1 기준 자료와 프로젝트 준비

- Next.js, UI, 테스트 실행 환경 초기화.
- 원본 Excel의 입력·가입 이력·시나리오·저장 결과를 필요한 범위만 추출.
- 입력 스키마와 초기 JSON 데이터 작성.
- 원래 값, 수정할 값, 수정 근거를 `financial-decisions.md`에 기록.
- 원본 자료, API 키, 로컬 환경 파일을 공개 결과물에서 제외하는 설정 작성.

완료 기준: 로컬 실행과 테스트가 가능하고, 기본 데이터가 스키마 검증을 통과하며 입력·출처의 연결을 추적할 수 있다.

### 2 계산 엔진 이식과 오류 수정

- 410개월의 수입·지출·대출·금융자산 계산 구현.
- 원본 E1~E6의 월별 금융자산을 재현해 이식 확인.
- 1988~1998년 연금 산식, 추납 계수, 연기연금 상한의 수정 반영.
- 세금·건강보험·구직급여 일정·주택연금 월액의 확인된 조건 반영.
- 원 단위 반올림 규칙과 비교 허용 오차 확정.
- 자산이 음수가 되는 구간은 누적 부족액으로 표시하고 자동으로 대출 실행·이자 발생을 가정하지 않음.
- 연별 집계, 최초 부족월, 최저 자산, 비상자금 충족 여부, 기말 자산 계산.

완료 기준: 원본 재현의 차이를 설명할 수 있고, 수정 모델은 독립 계산·확인된 참조값과 일치한다. 원본의 오류가 있는 결과를 수정 후 모델의 정답으로 고정하지 않는다.

우선 테스트는 퇴직 다음 달, 연금 개시월, 아내 근로 종료, 추납월, 상환월, 재취업 시작·종료, 최초 부족월이다. 전액 상환 이중 반영, 상환 후 이자 발생, 월·연간 집계 불일치도 확인한다.

### 3 입력·결과 화면

- 결과, 조건 설정, 비교, 가정·검증 근거의 4탭 구현.
- 핵심 4지표, 금융자산 추이, 연별 수입·지출, 월별 상세표 표시.
- 입력 검증과 기본값 복원 구현.
- 명목금액·2026년 구매력 기준의 단위 일관성 확보.
- PC에서는 조건·결과를 비교하기 쉽게, 모바일에서는 세로로 읽기 쉽게 구성.

완료 기준: AI 없이도 S0·S4 비교와 입력 변경에 따른 재계산을 사용할 수 있다.

### 4 시나리오 비교·저장·내보내기

- 7개 기본안과 사용자 변경안 비교.
- 재취업 1년 지연·실패, 생활비 증가, 물가·수익률 변화, 의료비 일시 지출 조작.
- 복사·이름 변경·삭제·초기화·localStorage 저장 구현.
- JSON 저장·불러오기, 월별 CSV, 그래프 이미지 저장 구현.

완료 기준: 조건을 바꾸면 지표·그래프·표가 함께 갱신되고, 저장 파일을 다시 불러오면 같은 조건·결과를 재현할 수 있다.

### 5 AI API와 계산 연결

`POST /api/ai`가 대화를 받고 Responses API의 함수 호출을 처리한다. 최초 도구는 다음 세 개로 한정한다.

- `simulate_scenario`: 기본안과 허용된 변경값으로 계산.
- `compare_scenarios`: 지정한 안의 지표·차이 반환.
- `get_evidence`: 등록된 출처 ID의 확인된 근거 반환.

질문 → AI 조건 제안 → Zod로 항목·범위·의미 검증 → 변경안 계산 → 결과를 AI에 전달 → 설명과 적용 변경을 화면에 표시하는 흐름이다. 기존 안은 보존하고 새 비교안을 만든다.

답변의 금액·날짜는 계산 결과를 사용하고 제도 설명은 등록 근거를 사용한다. 출처 ID가 실제로 존재하는지 검증한다. 근거가 없거나 시점·금액이 모호한 질문에는 필요한 정보를 다시 묻는다. AI가 제시한 임의 코드·파일 경로·URL을 실행하지 않는다.

API 키는 서버에서 관리하고 모델은 설정으로 선택한다. 도구 호출 횟수·답변 길이·타임아웃·호출 빈도를 제한한다. 실패하면 계산 결과를 유지하고 재시도할 수 있게 한다.

완료 기준: 아래 대표 질문에서 올바른 변경·계산·설명·추가 질문을 확인한다.

- ‘재취업이 1년 늦어지면?’
- ‘생활비를 월 280만 원으로 바꿔줘.’
- ‘2031년 가입안을 고른 이유가 뭐야?’
- ‘나중에 취업하면?’처럼 시점이 모호한 질문.
- 등록된 근거가 없는 제도에 대한 질문.

### 6 검증 증거와 사용성 마무리

- 실제 질문, 도구 인자, 결과 ID, 답변, 모델, 시각, 출처 ID 기록.
- 오류 수정 전후의 값·근거·검증 방법을 부록 자료로 정리.
- 대표 질문으로 AI 답변의 금액·날짜와 계산 결과 일치 평가.
- 화면, 초기화, 저장·재읽기, 내보내기, 오류 표시를 브라우저에서 확인.

완료 기준: 기획자들이 사용할 CSV·그래프·검증 기록을 받을 수 있고 실제 수행하지 않은 검증을 완료로 기록하지 않는다.

### 7 배포와 제출 준비

- Vercel 배포 설정·환경변수·타임아웃 구성.
- 배포 환경에서 기본 계산과 실제 AI 질문 확인.
- 심사자 접근 방법과 공개 범위를 정하고 별도 브라우저 상태에서 접속 확인.
- README에 실행·환경 설정·조작·계산 버전·알려진 한계 작성.
- 제출할 소스·실행 방법·이용 URL 준비.

완료 기준: 지정된 이용자가 배포 주소에서 계산·AI·내보내기를 사용할 수 있고, README에 따라 실행할 수 있다. 공모전의 외부 공개 조건도 충족한다.

| 11월 11~12일 | AI 함수 호출과 근거 설명 |
| 11월 13~14일 | 브라우저·실제 API 평가와 배포 |
| 11월 15일 | 최종 동작 확인과 제출물 확정 |
| 11월 16일 | 공모전 마감일, 예비 시간 |

계산 근거 확인을 기다리는 동안에는 같은 데이터 계약을 사용하는 화면 구현을 진행한다. 일정이 늦어지면 장식·추가 기능부터 줄이고 계산 수정, 비교, AI 주요 동작, 필수 내보내기를 우선한다.

## 기획자와의 분담·추가 확인

| 담당 | 책임·제공할 정보 |
| --- | --- |
| 개발 담당 | 계산 코드, 웹, AI, 테스트, 실제 실행 기록, 배포 |
| 기획자 측 | 최신 고객 설정, 공식 제도·산식 근거, 세금·보험·급여 처리, 조회한 주택연금 월액 |
| 기획자 측 | 본문 5·6단계, 채택안·비상자금 기준 판단, 본문·부록 수치 반영 |
| 공동 | 수정 모델 확인, AI 비용 예산, 데모 공개 범위, 제출·접근 방법 |

우선 받을 자료는 최신 Excel·Word, 생성 코드, 원 AI 대화와 실제 모델명, 원문 확인 증거다. 생성 코드가 없으면 현재 Excel을 추출 기준으로 사용한다.

실제 AI 호출 검증 전에 API 키와 사용 예산이 필요하다. 키는 개발 환경변수와 배포 설정에 넣고 채팅·저장소에는 남기지 않는다.
