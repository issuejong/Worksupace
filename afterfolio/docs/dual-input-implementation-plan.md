# Young Planner 대화·직접 입력 통합 구현 계획

작성일: 2026-11-05 · 기준 커밋: `62fe893`

## 1. 확정할 제품 동작

사용자는 챗봇과 대화하거나 입력 화면에서 직접 값을 설정할 수 있다. 두 방법은 같은 가구 정보·은퇴 계획을 공유하며, 언제든 섞어서 사용한다.

권 부장 부부는 **‘권 부장 부부 예시 넣기’를 눌렀을 때 값을 채우는 사례**로만 사용한다. 처음 접속할 때 예시 가구 정보나 예시 결과를 자동으로 보여주지 않는다. ‘권 부장 모드/내 정보 모드’ 같은 선택 UI도 다시 만들지 않는다.

이 문서는 구현 전 작성한 계획이다. 구현 및 검증 현황은 `dual-input-verification.md`를 참고한다.

## 2. 시작 화면과 사용 흐름

### 첫 화면

- 안내: ‘대화로 알려주거나 직접 입력해 은퇴 준비를 시작하세요.’
- 주요 동작: **대화로 정보 입력**, **직접 정보 입력**.
- 보조 동작: 기존 **권 부장 부부 예시 넣기**, **예시 소개**.
- 오른쪽 아래 로봇 버튼은 입력 전부터 사용할 수 있다.
- 결과 영역에는 ‘정보를 입력하면 결과가 표시돼요’와 필요한 정보 목록을 표시한다. 예시 금액·가짜 0원 결과를 표시하지 않는다.
- 두 주요 동작은 입력창을 여는 바로가기다. 선택해야만 사용할 수 있는 별도 모드나 서로 다른 데이터 저장소로 만들지 않는다.

### 대화로 입력

1. ‘대화로 정보 입력’이나 로봇 버튼으로 현재 플로팅 챗봇을 연다.
2. 이미 입력된 항목을 확인하고 빠진 항목만 한두 개씩 묻는다.
3. 사용자가 한 번에 여러 정보를 말하면 함께 추출한다.
4. AI는 정리한 값과 모호한 항목을 보여준다. 최초 입력은 여러 항목을 묶어서 확인할 수 있게 해 매 문장마다 별도 확인을 강요하지 않는다.
5. **정리한 정보 반영**을 누르면 공통 입력 상태와 직접 입력 화면에 반영한다.
6. 계산에 필요한 정보가 갖춰지면 계산하고 결과·계획 비교 상담으로 이어간다.

예: ‘예금 6천, 집 3억 5천, 대출 5천, 생활비는 월 250 정도예요.’ → 네 항목을 정리 → 은퇴 시기 등 부족한 정보 확인 → 반영 → 계산.

### 직접 입력

1. ‘직접 정보 입력’으로 기존 설정 패널을 연다.
2. 생활비·자산, 가족·은퇴 시점, 소득·퇴직금, 연금, 대출·세부 가정으로 묶어 입력한다.
3. 빈칸·입력 오류·필수 여부를 항목 옆에 표시한다. 필요한 정보를 채우면 기존처럼 결과를 갱신한다.
4. 중간에 챗봇으로 넘어가도 입력한 정보는 유지되고 빠진 정보부터 이어서 묻는다.
5. 챗봇으로 채운 값을 직접 수정하면 그 수정값을 이후 상담과 계산에 사용한다.

### 예시 넣기

- 버튼을 누르면 권 부장 부부의 가구 정보와 보고서 기본 계획을 한 번에 채운다.
- 현재 입력에 일부 예시값을 섞는 방식이 아니라 하나의 예시 시나리오로 교체한다.
- 이미 입력한 내용이 있었다면 **이전 입력으로 되돌리기**를 제공한다.
- 채워진 값의 출처는 내부적으로 ‘예시’로 기록한다. 일부를 직접 바꿨다고 나머지 예시값을 사용자에게 확인된 정보로 바꾸지 않는다.
- 예시를 넣거나 불러온 뒤에도 두 입력 방법을 그대로 사용할 수 있다.

## 3. 공통 입력 상태 설계

현재 `Planner`는 `h=example`, `s=adopted`로 시작한다. 이를 사용자 정보가 없는 입력 초안과 아직 적용하지 않은 은퇴 계획으로 바꾼다. 가구별 주택연금 연도·월액도 예시에서 가져오지 않는다.

### 입력 초안과 계산 입력 분리

- **입력 초안**: 빈칸·미확인·확인 대기 값을 담는다.
- **확정된 입력**: 직접 입력했거나 AI 확인 카드에서 반영한 값이다.
- **계산 입력**: 현재 조건의 필수 정보와 공통 가정을 검증해 생성하는 `Household`/`Solutions`다. 계산 엔진의 타입과 산식은 유지한다.

항목별로 값뿐 아니라 다음을 기록한다.

| 항목 | 내용 |
|---|---|
| 상태 | 미입력, 값 있음, 모름, 비해당, 가정 사용, AI 확인 대기 |
| 출처 | 직접 입력, 대화에서 확인, 예시, 파일 불러오기, 공통 가정 |
| 단위 | 만 원, %, 개월, 연월 등 엔진 기준 단위 |
| 버전 | 입력이 변경된 순서와 AI 제안의 기준 버전 |

‘자산 0원’과 ‘자산을 모름’을 구분한다. ‘연금이 없어요’와 ‘예상 연금액을 몰라요’도 구분한다. 모르는 정보를 0이나 권 부장 부부의 값으로 바꾸지 않는다.

### 하나의 갱신 경로

직접 입력·AI 확인·예시 넣기·파일 불러오기·계획 적용·되돌리기는 공통 상태 관리 함수를 거친다. 갱신 시 입력 버전을 증가시키고 필요한 계산과 상담 맥락을 함께 갱신한다.

AI가 읽은 뒤 사용자가 직접 값을 바꿨다면, 이전 버전의 AI 제안으로 새 값을 덮어쓰지 않는다. 충돌한 항목과 현재 값·제안 값을 보여주거나 현재 조건으로 다시 정리한다.

## 4. 어떤 정보를 언제 요구할지

사용자 개인정보와 공통 계산 가정을 분리한다.

- **기본 가구 정보**: 본인·배우자 출생연월, 은퇴/근로 종료 시점, 세후 소득, 월 생활비, 금융자산, 퇴직금, 예상 연금 등.
- **조건부 정보**: 대출이 있을 때 금리·잔여 기간, 주택연금을 비교할 때 주택 정보·시작 시점·월액 근거, 추납을 비교할 때 비용·추납 후 월액 등.
- **공통 계산 가정**: 물가·수익률·분석 기간 등. 기본 가정을 별도 표시하고 수정할 수 있게 한다.

실제 필수 항목은 계산 엔진의 의존 관계를 점검해 확정한다. 화면에서 보이는 항목만 줄이고, 엔진에 필요한 개인 값을 예시로 몰래 채우지 않는다.

- 비해당 항목은 사유와 함께 엔진의 중립값으로 연결한다. 예를 들어 대출 없음은 잔액 0으로 처리한다.
- 아직 준비되지 않은 방법을 탐색에서 활성화해 ‘추납 비용 0’ 같은 잘못된 추천을 만들지 않는다. 필요한 정보를 묻거나 해당 방법을 비교에서 제외한 범위를 명시한다.
- 모르는 필수 정보는 확인할 방법을 안내한다. 가정 사용을 허용할 항목은 사용자가 값·범위를 선택하고 결과에 가정임을 표시한다.
- 개인 가구 정보가 미완성인 동안 수치 분석 도구는 실행하지 않는다. 사용법·용어 설명·정보 입력 대화는 가능해야 한다.
- 완성된 입력을 수정하다 빈칸/오류가 생기면 재계산을 보류한다. 이전 결과를 남길 경우 ‘수정 전 계산 결과’임을 표시한다.

## 5. 챗봇 처리 구조

현재 Gemini API와 키 하나를 사용한다. 상담·정보 추출·분석·자료 설명을 코드와 도구로 분리하고, 모든 질문마다 여러 AI를 호출하지 않는다. 멀티에이전트 도입은 역할 혼동이 평가에서 확인될 때 검토한다.

### 입력 대화

- 이름 대신 실제 계산에 필요한 항목을 묻는다.
- 한 문장에서 여러 필드를 추출하고 원/만 원/억 원, 월/연, 세전/세후, 본인/배우자를 구분한다.
- ‘내년’처럼 월이 정해지지 않은 표현은 필요한 정보를 추가로 묻는다. 날짜 해석 기준은 한국 시간의 현재 날짜로 명시한다.
- ‘그중 주식 2천’과 ‘주식도 2천’처럼 합계 포함 여부를 구분한다. 불명확하면 금융자산을 중복 합산하지 않고 확인한다.
- 직접 입력한 필드를 다시 묻지 않는다. 이미 한 설명을 바탕으로 필요한 후속 질문을 고른다.
- 정리 결과는 허용된 필드의 구조화된 변경안으로 받고 코드로 타입·단위·범위를 검증한다.
- 사용자 확인 전에는 실제 계산 입력을 변경하지 않는다. 모호한 정보는 추정해 확정하지 않는다.

### API 변경

현재 `/api/agent`는 완성된 `householdSchema`를 요구하고, 프런트도 `result`가 없으면 전송을 막는다. 빈 상태에서 입력 대화를 하려면 양쪽을 함께 변경해야 한다.

- 수집 요청은 입력 초안·확인 상태·대화 맥락을 받을 수 있게 한다.
- 분석 요청은 완성도와 범위를 검증한 계산 입력을 요구한다.
- 입력 수집 중에는 입력안 작성·확인 질문 도구를 제공한다. 완성된 입력이 필요한 계산 도구는 서버에서 차단한다.
- 준비된 정보만으로 답할 수 있는 사용법·용어 질문은 계산을 강제하지 않는다.
- 기존 접근 토큰·요청 크기·호출 수·전체 시간 제한·키를 가린 오류 기록은 유지한다.
- 일반적인 정보 수집 한 턴은 모델 호출 한 번으로 추출과 다음 질문을 함께 처리하도록 설계한다. 유효성 오류·확인 질문은 예산 안에서 처리한다.

## 6. 상담·계산의 공통 기준

- 사용자가 어떤 경로로 입력했든 같은 값이면 같은 계산 결과가 나와야 한다.
- 결과 설명의 숫자·날짜·원인은 계산 근거와 대조한다. JSON 형식만 맞는 것을 정확한 설명으로 간주하지 않는다.
- 상담 목표와 고정 조건은 입력 방식 변경·후보 적용 후에도 유지한다. 과거 수치는 현재 입력으로 재계산해 사용한다.
- 비교나 탐색 요청은 설정을 자동 적용하지 않는다. 후보의 변경 조건을 확인하고 적용·되돌리기를 한다.
- AI 오류가 나도 직접 입력과 계산은 계속 사용할 수 있다. 챗봇의 실패를 제거했던 정형 계산 설명으로 대체하지 않는다.
- 기본 입력과 상담 맥락은 현재 세션의 메모리에만 둔다. 조건 JSON 저장·불러오기는 사용자 동작으로 유지한다.
- 현재 `Household`/`Solutions` 형식의 조건 파일은 호환한다. 새 출처·확인 상태 정보는 버전을 구분해 추가한다.
- 단일 사용자 부부 사례를 벗어나는 새 계산 산식, 금융계좌 자동 조회, 음성 입력, 자체 모델 학습은 이번 입력 통합의 범위에 넣지 않는다.

## 8. 구현 순서와 커밋

기존 AI 고도화 계획에서 뒤에 두었던 ‘대화 기반 입력’을 앞당긴다. 다음 8개 커밋을 1차 범위로 한다. 각 커밋에 관련 테스트와 문서 변경을 포함한다.

| 순서 | 예정 커밋 | 완료 내용 |
|---|---|---|
| 1 | `feat(AFPK): 가구 입력 초안과 공통 상태 관리 추가` | 미입력/0/모름·출처·버전·엔진 변환 경계 |
| 2 | `style(AFPK): 빈 시작 화면과 두 입력 진입점 구성` | 자동 예시 제거, 대화·직접 입력 바로가기, 결과 대기 상태 |
| 3 | `feat(AFPK): 직접 입력의 필수 항목과 계산 연결 개선` | 조건부 필수 입력·오류·가정 구분·계산 준비 상태 |
| 4 | `feat(AFPK): 챗봇 문진과 가구 정보 추출 추가` | 빈 상태 대화, 다중 필드 추출, 누락/모호함 확인 |
| 5 | `fix(AFPK): AI 입력안 확인과 수정 충돌 처리` | 확인 후 공통 상태 반영·직접 수정 동기화·되돌리기 |
| 6 | `fix(AFPK): 예시 입력과 사용자 정보의 출처 분리` | 명시적 예시 채움·전체 교체·이전 입력 복원·대화 버전 정리 |
| 7 | `fix(AFPK): 상담 맥락과 계산 근거 검증 연결` | 입력 방식 변경 후 대화 유지·잘못된 분석 차단 |
| 8 | `fix(AFPK): 대화와 직접 입력의 통합 흐름 검증` | 회귀 질문·실제 모델 평가·PC/모바일·안내 갱신 |

이후에는 기존 AI 고도화 계획의 목표·제약 기반 탐색, 생활비 한도, 위기 분석, 검토 자료 검색을 이어간다. 이번 계획에서 선행 구현한 대화 입력·맥락·검증은 다시 구현하지 않고 합쳐서 보완한다.

## 9. 검증 기준

### 자동 검증

- 최초 화면에 권 부장 부부 값과 결과가 자동으로 들어가지 않음.
- 같은 정보를 직접 입력한 경우와 대화 확인으로 반영한 경우의 엔진 입력·계산 결과 일치.
- 미입력/모름은 0으로 바뀌지 않으며 개인 필드에 예시 fallback이 없음.
- AI가 말하지 않은 항목을 확인된 사용자 값으로 생성하지 않음.
- 단위·세전/세후·대상·합계 포함 여부가 모호하면 확인 요청.
- 직접 입력 도중 AI로 전환하거나 그 반대인 경우 값이 보존됨.
- 오래된 AI 응답이 새 수동 입력을 덮어쓰지 않음.
- 예시 넣기 후 기존 보고서 기준값 재현, 되돌리기 후 이전 입력·출처 복원.
- 조건부 정보가 없는 준비 방법을 임의의 0 비용 등으로 최적안에 포함하지 않음.
- 기존 조건 파일 호환과 명시적 저장/불러오기 유지.
- 기존 엑셀 7개 안 × 410개월 = 2,870개월 회귀 대조 유지.
- 타입 검사·프로덕션 빌드·기존 도구 및 오류 처리 테스트 통과.

### 실제 브라우저 흐름

1. **처음 방문 → 직접 입력만 → 결과 확인**. AI 키가 없어도 가능해야 한다.
2. **처음 방문 → 대화만 → 정리 카드 확인 → 반영 → 결과 확인**.
3. **직접 입력 일부 → 챗봇이 빠진 정보 수집 → 결과 확인**.
4. **대화로 반영 → 직접 생활비 수정 → 챗봇에 후속 질문**.
5. **AI 정리 중 수동 수정 → 이전 제안 도착 → 충돌 항목 확인**.
6. **예시 넣기 → 결과/소개 확인 → 직접 또는 대화로 사례 변경 → 이전 입력 복원**.
7. **모르는 연금액·모호한 금액 표현 → 확인 질문·가정 사용 여부 → 계산 상태 확인**.
8. **모바일 로봇 버튼·스크롤 고정·Enter/Shift+Enter·닫기/재열기·키보드 이동**.

정확한 수치·상태·입력 권한은 코드로 검사하고, 문진의 자연스러움·질문 수·설명 품질은 대표 대화로 실제 모델을 평가한다. 실제 모델 평가는 명시적인 실행 명령으로 진행하며 기본 테스트에 외부 API 호출을 넣지 않는다.

## 10. 작업·배포 기준

원래 `Worksupace/afterfolio`에서 작업한다. 기존 사용자 수정과 다른 프로젝트 파일은 건드리지 않는다. 구현 후 먼저 로컬에서 두 입력 경로와 예시 동작을 검토하고, 푸시·배포는 별도 요청 때 진행한다.
