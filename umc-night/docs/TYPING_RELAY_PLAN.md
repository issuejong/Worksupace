# 모바일 타자 릴레이 구현 초안

작성일: 2026-10-23 (Asia/Seoul)

구현 기준과 검증 범위를 기록한다. 차례 수는 기본 5회(1~10회 편집 가능), 우승팀 누적 반영은 기본 꺼짐이며 운영자가 선택한다.

## 1. 게임 콘셉트와 확정 범위

- 팀별 기존 대표 휴대폰 한 대를 팀원들이 차례로 돌려 사용한다. 새 참가 계정이나 QR은 필요 없다.
- 진행자가 직접 등록한 문장을 보고 입력한다. 모든 팀은 같은 순서의 같은 문장을 입력한다.
- 팀의 마지막 차례 제출까지 시간을 재고 오타 제출에 벌칙 시간을 더한다.
- 기록이 짧은 팀이 승리한다. 입력하는 동안 고친 오타에는 벌칙이 없고, 틀린 상태로 제출한 경우에만 +1초다.
- 한 번의 잘못된 제출에 오타가 여러 글자 있어도 벌칙은 +1초다.

### 확정된 오타 처리 규칙

사용자 답변에 따라 **오타 제출마다 벌칙 +1초를 누적하고, 같은 사람이 현재 문장을 정확히 고쳐 다시 제출해야 다음 차례로 이동**하는 방식으로 확정한다.
틀린 입력은 수정할 수 있도록 유지하며, 수정·재제출하는 동안에도 실제 경과 시간은 계속 흐른다. +1초는 최종 기록에 더하는 벌칙이며 별도의 1초 대기 시간을 강제하지 않는다.

### 아직 확정하지 않은 추천 기본값

- 팀당 5차례. 팀원이 5~6명인 점을 고려해 경기별 차례 수를 모든 팀에 동일하게 적용한다.
- 각 차례 문장을 따로 입력할 수 있게 하고, 같은 문장을 반복하고 싶으면 `전체 차례에 적용`을 사용한다.
- 1~10차례, 문장당 한 줄 1~200자. 일반 한글·영문·숫자·문장부호를 허용하며 첫 버전에서 이미지·서식·줄바꿈은 제외한다.
- 모든 팀 완료를 기다리는 것을 기본으로 하되 진행자가 사유를 입력해 강제 마감할 수 있다. 미완료 팀은 DNF로 표시하고 완료 팀 뒤에 둔다.
- 새 게임의 기록 순위는 반드시 제공한다. 기존 누적 정답 개수에 연결하는 경우에는 이 게임 우승팀만 1개를 얻는 방식을 제안하며, 사용자 합의 전 자동 반영하지 않는다.

## 2. 진행 흐름

1. 행사 준비에서 `타자 릴레이` 유형을 선택하고 게임 제목·차례 수·차례별 문장을 저장한다.
2. 진행자가 해당 게임을 열면 모바일에 규칙과 첫 문장을 미리 보여준다. 팀은 `준비 완료`를 누른다.
3. 참가 팀 목록과 문장 목록을 이 실행에 고정한다. 경기 중 새로 등록된 팀은 다음 게임부터 참가한다.
4. 전 팀 준비를 확인한 뒤 진행자가 시작한다. 서버가 5초 뒤의 공통 시작 시각을 정한다.
5. 모바일은 이미 받아둔 문장과 시작 시각으로 카운트다운하고 동시에 입력을 활성화한다.
6. 제출은 서버가 현재 차례·문장·기록을 검증한다. 정답이면 입력칸을 비우고 다음 차례로 자동 전환한다. 응답에 다음 문장을 실어 상태 조회를 기다리지 않는다.
7. 모바일에 `2 / 5번째 차례 · 다음 사람에게 넘겨주세요`를 표시한다. 휴대폰 전달 시간도 총시간에 포함한다. 실제로 다른 사람이 입력하는지는 현장 진행자가 확인한다.
8. 오타 제출은 +1초를 기록하고 입력 내용을 유지한다. 같은 사람이 수정해 정확히 재제출할 때까지 다음 차례로 넘어가지 않는다.
9. 마지막 차례의 정답 제출이 접수되면 팀 기록을 고정하고 추가 제출을 차단한다.
10. 모든 팀 완료 또는 진행자의 강제 마감 후, 진행자가 `결과 공개`를 누른다. 다음 게임으로 넘어가거나 기존 라운드 결과 화면으로 이어진다.

첫 문장을 준비 단계부터 보여주는 이유는 기존 2초 간격 조회 때문에 팀마다 문장을 늦게 받는 차이가 생기지 않게 하기 위해서다. 시작 직전에 내용을 받아야 하는 비공개 퀴즈와는 공개 정책을 구분한다.

## 3. 시간과 순위

공식 기록(ms) = 마지막 정답 제출의 서버 수신 시각 - 공통 시작 시각 - 진행자 일시정지 시간 + 잘못된 제출 횟수 × 1,000

- 클라이언트는 문장·차례·요청 ID만 전송한다. 클라이언트가 보낸 기록, 벌칙 횟수, 완료 상태는 신뢰하지 않는다.
- 서버가 기록을 확정하고 DB에 저장한다. 화면에는 서버 시각과 맞춘 스톱워치를 표시하며 매 순간 서버 요청을 보내지는 않는다.
- 팀이 끝난 뒤에는 뒤이은 일시정지 시간이 이미 확정된 팀 기록에 영향을 주지 않는다.
- 일시정지 중에는 타이머와 제출을 모두 멈춘다. 재개 시 같은 입력 차례를 이어간다.
- 폰 전달·입력 수정·통신에 걸린 시간은 실제 소요 시간에 포함한다. 순위를 가르는 제출의 통신 지연은 서버 기준 기록에도 반영되므로 전 팀을 동일한 현장 와이파이로 리허설한다.
- 0.01초 단위 공식 기록을 화면과 순위에 일관되게 적용하고, 같은 기록은 공동 순위로 처리한다.
- 실제 제출 완료 순서와 벌칙을 더한 순위는 다를 수 있다. 완료 시에는 `잠정 기록`으로 안내하고 마감 후 최종 순위를 확정한다.

예시:

| 팀 | 실제 소요 시간 | 오타 제출 | 벌칙 | 공식 기록 | 순위 |
|---|---:|---:|---:|---:|---:|
| A | 42.30초 | 3회 | +3초 | 45.30초 | 2위 |
| B | 43.20초 | 0회 | +0초 | 43.20초 | 1위 |
| C | 44.00초 | 2회 | +2초 | 46.00초 | 3위 |

## 4. 문자열과 모바일 입력 규칙

- 기본 판정은 문장 전체 일치다. 띄어쓰기·문장부호·영문 대소문자를 비교한다.
- 등록 문장과 입력 모두 유니코드를 NFC로 정규화하고 양끝 공백만 제거한다. 문장 중간 공백이나 문장부호는 임의로 삭제하지 않는다.
- 한글 자모가 아직 조합 중인 상태에서 Enter를 눌러도 제출하지 않는다. 명시적인 큰 제출 버튼을 기본으로 사용한다.
- 제출 처리 중 버튼을 잠그고, 같은 요청 재전송은 저장된 결과만 반환한다. 벌칙이나 차례를 중복 반영하지 않는다.
- 붙여넣기는 막고 입력칸의 자동 완성·자동 교정·자동 대문자화를 끄도록 요청한다. 브라우저에서 제어할 수 있는 범위만 적용한다.
- 긴 문장은 줄바꿈 표시하되 입력 내용에는 줄바꿈을 요구하지 않는다. 키보드가 올라와도 문장·현재 차례·제출 버튼이 가려지지 않아야 한다.
- 타이머나 상태 조회가 갱신될 때 입력칸을 다시 생성하지 않으며, 타이핑 중인 글자·포커스·스크롤을 유지한다.

## 5. 화면

### `/admin/setup`

- 기존 문제 유형에 `타자 릴레이` 추가.
- 게임 제목, 공통 차례 수, 차례별 문장 입력·수정·삭제·순서 변경, 한 문장 전체 적용.
- 미리보기: 모바일에서 문장이 어떻게 보이는지와 1차례당 문장 길이 확인.
- 기존 퀴즈 전용 정답 방식·선택지·전원 답안 제출·배점 입력은 타자 유형 폼에서 숨긴다.
- 시작한 실행은 등록 원본을 편집해도 변하지 않도록 스냅샷을 고정한다.

### `/play`

- 준비: 규칙, 첫 문장, 전체 차례 수, `준비 완료`.
- 진행: 팀 이름, 현재 차례, 따라 칠 문장, 입력칸, 큰 `제출` 버튼, 실제 경과 시간, 벌칙 `+2초`.
- 오타: `문장이 일치하지 않아요 · +1초`, 입력 유지.
- 다음 차례: 자동 초기화와 교대 안내.
- 완료: 실제 시간 + 벌칙 = 잠정 기록, 결과 대기.
- 연결 끊김: 저장 여부와 재시도 안내. 재전송은 같은 요청 ID를 재사용한다.

### `/screen`

- 진행 중: 게임 제목, 전체 경과 시간, 팀별 `3 / 5` 진행 막대, 완료 여부. 누적 종합 순위는 기존 공개 시점을 따른다.
- 결과 공개: 팀별 순위, 실제 시간, 오타 횟수, 벌칙, 공식 기록. 미완료 팀은 별도 표기.
- 디자인은 기존 UMC Night 색상·카드·글꼴을 사용하고 타자 진행 막대를 추가한다.

### `/admin/live`

- 팀별 준비/접속 상태, 현재 차례, 벌칙, 완료 기록.
- `시작`, `일시정지/재개`, `강제 마감`, `결과 공개`, `게임 무효`, `다음 문제`.
- 전 팀이 완료하지 않았으면 기본 마감은 차단한다. 강제 마감은 별도 버튼과 사유를 사용한다.
- 기록을 임의로 덮어쓰는 기능은 첫 버전에서 제외한다. 통신·출제 문제 발생 시 게임 전체를 무효 처리하고 재경기용 새 문제를 등록한다.

## 6. 현재 코드에 적용할 구조

기존 Next.js 서버 API·Supabase Postgres·팀 세션·상태 조회 구조를 그대로 사용한다. 유료 API나 WebSocket 서비스는 추가하지 않는다.

| 변경 영역 | 계획 |
|---|---|
| `questions`와 준비 API | `kind = typing`과 문장 배열 추가. 타자 설정을 다른 퀴즈 설정과 분리해 검증 |
| `run_questions` 스냅샷 | 시작 당시 문장 순서·참가 팀·판정 규칙·벌칙을 고정 |
| `typing_runs` 신규 | 해당 문제 실행, 공통 시작 시각, 진행 중 정지 시각, 누적 정지 시간 |
| `typing_team_progress` 신규 | 팀별 준비 여부, 현재 차례, 벌칙 횟수, 완료 시각, 확정 기록, 버전 |
| `typing_attempts` 신규 | 실행·팀·차례·요청 ID, 입력, 판정, 서버 수신 시각. 같은 요청에는 같은 결과 반환 |
| `/api/typing` 신규 | 팀 준비와 타자 제출. 팀 신원은 기존 쿠키에서 판단 |
| `/api/state` 확장 | 타자 전용 진행 데이터. 팀에는 자기 입력/현재 문장, 현장에는 공개용 진행 상황만 제공 |
| 진행 API·채점 | 기존 단계에 타자 게임 분기를 추가하고, 종료·결과 공개·무효·선택적 누적 반영을 연결 |
| 삭제·초기화·내보내기 | 타자 기록이 있는 팀/문제의 삭제 보호, 리허설 초기화, JSON 결과 내보내기에도 포함 |

- 서버 로직은 `lib/server/typing.ts`, 순수 판정·계산은 `lib/typing.ts`, 모바일 UI는 별도 컴포넌트로 분리한다.
- `lib/server/game.ts`와 `lib/client.ts`의 유형/상태를 확장한다. 기존 일반 퀴즈 제출 경로로 타자 기록을 변경할 수 없게 한다.
- 시작 전·일시정지·마감·완료 후 제출을 차단하고, 이전 차례 요청으로 다음 차례를 건너뛸 수 없게 한다.
- 팀별 차례와 벌칙 변경은 트랜잭션·버전·요청 ID로 묶는다. 전체 실행 잠금은 필요한 범위로 제한해 여러 팀의 동시 제출이 불필요하게 직렬화되지 않게 한다.
- 진행 화면의 현재 2초 간격 조회는 유지한다. 정답·오타 판정은 제출 API 응답으로 즉시 반영하며, 스톱워치는 브라우저에서 갱신한다.
- 새로고침 시 차례·벌칙·완료 기록을 서버에서 복구한다. 아직 제출하지 않은 입력은 해당 실행·팀·차례에 묶어 `sessionStorage`에 임시 보관하고, 차례 변경·종료·로그아웃 시 삭제한다.
- 네트워크가 끊겨도 공식 시간은 계속 흐른다. 로컬 완료 기록을 뒤늦게 소급 제출하지 않는다. 광범위한 현장 장애는 진행자가 일시정지하거나 무효 처리한다.

## 7. 커밋 단위 구현 순서

1. `feat(umc-night): add typing relay configuration`
   - 마이그레이션·형식·설정 검증, 준비 화면 문장 편집과 미리보기.
   - 신규 마이그레이션을 `scripts/migrate.mjs`에 등록하고 기존 문제/팀/행사 데이터를 보존한다.
   - 설정 왕복 저장, 차례 수/문장 제한, 기존 퀴즈 회귀를 확인한다.
2. `feat(umc-night): implement authoritative typing relay engine`
   - 준비, 동시 시작, 제출 판정, +1초, 차례 전환, 완료 기록, 요청 중복 방지.
   - 정지/재개·마감·동시 제출·순위 계산을 실제 별도 테스트 DB로 검증한다.
3. `feat(umc-night): add mobile typing relay experience`
   - 준비 화면, 타이머, 입력/교대/오타/완료, 한글 조합, 재접속 복구.
   - iOS Safari와 Android Chrome의 실제 키보드에서 입력과 버튼 가시성을 검증한다.
4. `feat(umc-night): add typing relay host controls and results`
   - 진행자 제어, 대형 화면 진행 막대와 결과표, 기존 라운드 공개 흐름, 합의한 누적 반영.
   - 무효·재경기, 팀/문제 삭제 보호, 리허설 초기화, 결과 내보내기를 연결한다.

## 8. 완료 기준과 첫 버전 경계

- 운영자가 코드를 수정하지 않고 문장과 순서를 자유롭게 저장·변경할 수 있다.
- 모든 참가 팀이 같은 차례 수와 문장 순서로 진행한다.
- 오타 제출 3회는 정확히 +3초이며, 통신 재시도는 벌칙을 중복 부과하지 않는다.
- 모든 차례의 문장이 정확해야 완료되고 서버에서 고정한 기록대로 순위가 결정된다.
- 새로고침으로 시간이나 벌칙이 초기화되지 않으며, 완료된 팀 기록은 다른 팀 진행 중에도 변하지 않는다.
- 타자 게임을 마치고 객관식·OX·주관식으로 이어가도 기존 진행과 누적 결과가 유지된다.
- 첫 버전에는 개인별 로그인·타수 통계·개인 순위·매 글자 실시간 중계·복잡한 기록 정정 기능을 넣지 않는다.

오타 제출 후 같은 사람이 수정하는 규칙을 적용한다. 공통 차례 수는 기본 5회로 두되 운영자가 변경하며, 우승팀 누적 정답 +1은 기본 꺼짐 옵션으로 제공한다. 문구와 순서는 준비 화면에서 변경한다.
