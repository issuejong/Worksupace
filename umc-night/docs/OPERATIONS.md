# UMC Night 운영 가이드

[프로젝트 README로 돌아가기](../README.md)

## 1. 행사 준비

진행자 노트북과 대형 화면은 **확장 화면**으로 연결합니다. 노트북에는 `/admin/live`, 대형 화면에는 `/screen`을 띄웁니다. 팀별로 대표 휴대폰 한 대를 사용합니다.

1. `/admin/setup`에서 라운드와 순서를 정합니다.
2. 문제 유형·정답 방식·배점·제한 시간을 입력합니다. 같은 라운드의 문제는 목록에서 드래그해 정렬할 수 있습니다.
3. 현장 화면의 QR을 스캔해 팀 이름을 등록합니다. 같은 이름은 중복 등록할 수 없습니다.
4. `/admin/live`에서 연습 게임을 만들고 실제 기기로 리허설합니다.
5. 리허설 기록을 정리한 뒤 실제 게임을 생성합니다. 종료하지 않은 게임이 있으면 새 게임을 만들 수 없습니다.

일반 퀴즈도 문제 시작 전에 팀을 등록하는 것이 좋습니다. **전원 제출 대기와 타자 릴레이의 참가 대상은 문제를 열 때 등록된 팀으로 고정됩니다.**

라운드별 보기는 목록을 필터링하는 기능이며, 출제 순서를 바꾸지는 않습니다. 출제는 라운드 순서와 각 라운드의 문제 순서를 따릅니다. 실제 문제의 제목·정답·미디어·배점은 DB에서 관리하며 저장소에 실전 데이터가 포함되지는 않습니다.

## 2. 퀴즈 진행과 채점

기본 흐름은 다음과 같습니다.

```text
문제 시작 → 팀별 답안 제출 → 정답 공개 · 채점 확정 → 다음 문제
```

답변 마감과 정답 공개·채점은 나눠 진행할 수도 있습니다. 답변 마감 뒤에도 객관식·O/X 선택지는 남아 있으며, 일시정지 후에는 남은 시간으로 재개합니다.

| 정답 방식 | 진행 방법 |
|---|---|
| 미리 정답 입력 | 등록한 정답으로 채점. 주관식 유사 답안은 진행자가 인정 여부를 조정 |
| 현장 정답 선택 | 답변 중에도 공개할 정답을 입력·선택. 공개 버튼을 누를 때 확정 |
| 팀별 직접 판정 | 주관식 답안을 읽고 제출한 각 팀에 정답·오답 선택. 정답 문구는 공개용이며 자동 채점에 사용하지 않음 |

직접 판정은 제출한 모든 팀을 판정해야 확정할 수 있습니다. 팀이 답안을 수정하면 판정을 다시 해야 하며, 서버도 답안 버전을 대조합니다. 확정 전 판정은 진행자 화면의 임시 상태이므로 새로고침하면 다시 선택해야 합니다. 미제출 팀은 0점입니다.

자동 비교하는 주관식은 한글 NFC 정규화, 앞뒤 공백 제거, 대소문자 무시를 적용합니다. 문장 중간 띄어쓰기나 유사 표현까지 자동으로 인정하지는 않습니다.

### 점수 규칙

- 퀴즈 정답 배점은 **1~1,000점 정수**, 기본값은 1점입니다. 오답은 0점입니다.
- **정답 팀 모두 집계** 또는 **첫 정답 제출 팀만 집계**를 선택합니다. 선착순은 저장된 답안의 제출·수정 시각 순서로 판단하므로 답안 수정이 순서에 영향을 줄 수 있습니다.
- **전원 제출 대기**는 시간 제한을 적용하지 않고, 시작 당시 팀 모두가 제출해야 마감·공개할 수 있습니다. 자동으로 다음 문제로 이동하지는 않습니다.
- **연습 문제**로 설정한 문제는 득점하지 않습니다. **연습 게임 모드** 자체는 점수 흐름을 테스트하기 위해 점수를 기록하며, 나중에 초기화할 수 있습니다.
- 배점·정답 방식·문장·참가 대상은 문제 시작 시 스냅샷으로 고정합니다. 시작 후 원본 문제를 편집해도 진행 중인 기록은 바뀌지 않습니다.
- 채점 후 판정을 정정하면 점수 차액과 사유가 이력에 남습니다. 선착순 문제는 새 첫 정답 팀을 다시 계산합니다.
- 문제 무효 처리는 해당 문제에서 부여한 점수를 취소합니다. 동점은 공동 순위입니다.

### 라운드와 최종 결과

라운드 마지막 문제도 먼저 정답·채점 결과를 확인합니다. 이후 **중간 순위 공개**를 눌러 누적 점수를 보여주고 다음 라운드로 넘어갑니다.

마지막 라운드는 **오늘의 우승팀은? 띄우기**를 누르면 현장·참가자 화면에 발표 대기 화면을 띄웁니다. 이때 최종 누적 점수는 숨깁니다. **우승팀 공개!**를 누르면 공동 우승을 포함한 최종 결과를 공개합니다.

## 3. 타자 릴레이

### 설정

`행사 준비 → 문제 편집`에서 유형을 **타자 릴레이**로 선택합니다. 기본 5차례이며 1~10차례로 바꿀 수 있고, 모든 팀이 같은 문장 순서로 진행합니다. `첫 문장을 전체 차례에 적용`으로 같은 문장을 반복할 수 있습니다.

**득점 경기로 운영하려면 두 항목을 모두 확인하세요.**

1. **우승팀 점수를 누적 점수에 반영**을 켭니다. 기본값은 꺼짐입니다.
2. **우승팀 배점**을 입력하고 저장합니다.

점수 반영을 끄면 순위만 정하고 점수는 주지 않습니다. 배점을 입력했어도 이 옵션이 꺼져 있으면 0점입니다. 시작 후 설정을 바꿔도 이미 열린 경기에는 소급 반영되지 않습니다.

### 진행

1. 진행자가 문제를 열면 시작 당시 팀과 문장 설정이 고정됩니다. 참가자에게 문장은 시작 시각 이후 표시됩니다.
2. 모든 팀이 모바일에서 **준비 완료**를 누릅니다.
3. 진행자가 **전 팀 동시 시작**을 누르면 5초 카운트다운 후 공통 시작 시각에 입력할 수 있습니다.
4. 한 사람이 정확히 제출하면 다음 차례로 넘어가고 휴대폰을 다음 사람에게 전달합니다.
5. 오타로 제출하면 **제출 1회당 +1초**를 누적합니다. 같은 사람이 수정해 정확히 제출해야 다음 차례로 넘어갑니다. 입력·전달 시간도 기록에 포함됩니다.
6. 전 팀 완료 후 **전 팀 완료 · 결과 공개**로 순위와 점수를 확정합니다.

타자 입력은 앞뒤 공백과 한글 유니코드 표현 차이를 정규화합니다. 중간 띄어쓰기·대소문자·문장부호는 같아야 합니다.

```text
공식 기록 = 시작부터 마지막 제출까지의 시간
           - 진행자 일시정지 시간
           + 오타 제출 횟수 × 1초
```

마지막 정답 요청이 API에 도착한 시각을 DB 시간대에 맞춰 기록합니다. 서버 내부 대기는 보정하지만 휴대폰에서 서버까지의 통신 지연은 포함됩니다. 기록은 0.01초 단위로 정렬하며, 같은 기록은 공동 순위입니다. 점수 반영을 켠 경기는 공동 우승팀 모두에게 설정한 배점을 부여합니다.

미완료 팀이 있으면 사유를 적어 **강제 마감**할 수 있으며, 해당 팀은 DNF로 표시합니다. 타자 기록은 수동 정정 기능을 제공하지 않으므로 문제가 생긴 판은 무효 처리하고 재경기 문제를 등록합니다.

### 새로고침과 연결 장애

차례·벌칙·완료 기록은 DB에서 복구합니다. 미제출 입력과 응답을 확인하지 못한 제출 요청은 가능한 경우 현재 탭의 `sessionStorage`에 보관하며, 같은 요청 ID로 재확인합니다.

연결이 끊겨도 공식 시간은 자동으로 멈추지 않습니다. 여러 팀에 장애가 발생하면 진행자가 일시정지하거나 무효 처리해야 합니다. 한글 조합·자동 교정·화면 키보드는 실제 iOS Safari와 Android Chrome에서 확인하세요.

## 4. 사진과 유튜브

### 눈코입 사진 퀴즈

1. **눈코입 퀴즈 새로 만들기**로 주관식·팀별 직접 판정 문제를 준비합니다.
2. **문제 사진**에 잘라둔 사진을 올립니다. 정답 이름과 **정답 공개 사진**은 선택적으로 등록합니다.
3. 사진과 배점을 확인하고 **문제 추가 / 문제 수정**을 눌러 저장합니다. 업로드만 해서는 문제에 연결되지 않습니다.

JPG·PNG·WebP 파일을 선택할 수 있습니다. 브라우저에서 원본 최대 30MB를 받아 긴 변을 최대 1,600픽셀로 줄이고 3MB 이하로 재인코딩합니다. HEIC는 JPG로 변환해야 합니다. 사진 연결 해제는 문제의 연결만 없애며 저장된 파일을 삭제하지 않습니다.

문제 사진은 출제 시 공개하고 정답 사진은 정답 공개 후에만 제공합니다. 같은 브라우저의 진행자·현장 탭은 다음 문제 사진을 메모리에 미리 읽어 전환을 준비합니다. 다음 정답 사진은 사전 전달하지 않습니다.

### 가사 퀴즈와 정답 공개 영상

**정답 공개 영상**에 유튜브 링크와 시작 시간을 입력합니다. `1:20`, `80`, `1:02:03` 형식을 지원합니다. 시간 칸을 비우면 링크의 시작 시간을 사용하고, 링크에도 없으면 처음부터 재생합니다. 별도로 입력한 시간이 우선하며 `0`은 처음부터 재생입니다.

문제 진행·일시정지·마감 중에는 영상 정보를 보내지 않습니다. 정답 공개 후 대형 화면의 위쪽에 정답, 아래에 가사와 영상, 그 아래 팀별 답안을 표시합니다. **영상 재생**을 누르면 설정 구간부터 시작하고 **설정 구간부터 다시 재생**으로 돌아갈 수 있습니다. 참가자 휴대폰에는 영상 플레이어를 넣지 않습니다.

영상은 유튜브 임베드이므로 인터넷이 필요합니다. 광고·자동재생 제한·외부 재생 제한이 있을 수 있으며, 시작 구간이 프레임 단위로 정확하게 맞는다고 보장하지 않습니다. 행사장 노트북과 음향에서 미리 재생해 보세요.

## 5. 대표 휴대폰 교체

진행자 화면에서 해당 팀의 **기기 이전 QR**을 발급하고 새 휴대폰으로 스캔합니다. **이 기기로 이어하기**를 누르면 팀 이름·답안·점수는 유지되고 기존 기기의 팀 세션이 해제됩니다.

QR은 5분 동안 한 번만 사용할 수 있으며 다시 발급하면 이전 QR은 무효가 됩니다. 팀 세션은 12시간이므로 행사 직전에 실제 대표 기기로 등록하는 것이 좋습니다. 쿠키 삭제나 브라우저 변경으로 팀 접속이 사라졌을 때도 새 팀을 중복 생성하기보다 이 기능을 사용합니다.

## 6. 리허설·초기화·백업

| 도구 | 범위 |
|---|---|
| 라운드 스킵 · 테스트용 | 연습 모드에서만 제공. 진행 중이거나 다음에 진행할 라운드의 미완료·미진행 문제를 무득점으로 건너뛰고 채점 완료 점수는 유지 |
| 연습 데이터 초기화 | 최근 게임이 연습 모드일 때 해당 게임 기록만 삭제. 팀·문제는 유지 |
| 팀·게임 초기화 | 실제 행사와 연습을 포함한 모든 게임 기록·팀·세션·기기 이전 QR 삭제. 문제·라운드·이미지·진행자 계정은 유지 |
| 결과 JSON 저장 | 최근 게임의 문제 스냅샷, 답안, 채점, 점수 이력, 타자 기록 내보내기 |

초기화는 복구 기능을 제공하지 않습니다. **먼저 결과 JSON을 저장하세요.** 팀·게임 초기화는 삭제 대상을 확인하고 `팀 초기화`를 직접 입력해야 실행됩니다. 확인 후 상태가 달라지거나 다른 요청이 처리 중이면 재확인을 안내합니다.

내보낸 JSON에는 답안과 문제 정답이 포함됩니다. 필요한 사람에게만 전달하세요. JSON을 자동으로 다시 불러와 복구하는 기능은 없습니다.

PPT·진행 대본 같은 별도 백업은 DB와 자동으로 동기화되지 않습니다. 문제·배점·타자 문장·영상 구간을 바꿨다면 백업도 갱신해야 합니다. 전체 서버 장애 시 사이트만으로 진행할 수 없으므로 백업 자료와 수기 점수표를 행사 노트북에 저장해 두세요.

## 7. 동기화와 DB 연결

- Realtime은 DB 변경 신호만 전달하고 각 화면은 권한에 맞는 상태 API를 재조회합니다. 연결 실패 시 약 0.75~1초 조회로 대체하며, 정상 연결 중에도 10초 간격 안전 조회를 합니다. 행사 준비 목록은 3초 간격으로 갱신합니다.
- 진행자 동작 응답에는 최신 상태를 포함하고, 같은 브라우저 탭에는 BroadcastChannel 알림도 전송합니다.
- `/api/clock`의 DB 시각과 왕복 시간을 사용해 화면 시간을 보정합니다. 초기 3회 측정 뒤 15초마다 갱신하며, 측정 사이에는 `performance.now()`로 시간을 계산합니다. 기기별 표시가 항상 0.01초까지 일치한다고 보장하지 않으며 공식 기록은 서버 값을 사용합니다.
- Vercel 서버 인스턴스별 Postgres.js 연결은 최대 1개, 유휴 해제 5초, 최대 수명 60초입니다. 인스턴스가 늘면 전체 DB 연결도 늘어날 수 있습니다.
- 일반 API는 Session pooler를 사용하고, 배포 마이그레이션은 같은 Supabase 호스트의 Transaction pooler `6543`으로 변환해 명시적 트랜잭션 안에서 실행합니다. 이 변환은 로컬·직접 연결 주소에는 적용하지 않습니다.

## 8. 시작 전 체크리스트
