# UMC Night

동국대학교 UMC 동아리 MT를 위한 현장 퀴즈 사이트입니다. 진행자는 노트북에서 문제를 운영하고, 팀 대표는 휴대폰으로 답안을 제출하며, 대형 화면에는 문제와 공개된 결과가 나타납니다.

## 현재 구현

- 주관식·객관식·O/X, 문제·정답 공개 이미지, 라운드와 출제 순서
- 모바일 타자 릴레이: 1~10차례 문장 자유 등록, 팀별 폰 돌려쓰기, 전 팀 준비 후 동시 시작, 오타 제출마다 +1초·정확히 수정 후 다음 차례, 서버 기준 기록 순위
- 타자 경기 일시정지·재개, 사유를 남기는 강제 마감과 미완료(DNF), 공동 순위, 우승팀 누적 점수 +1점 선택(기본 꺼짐)
- 문제별 `미리 정답 입력` 또는 `현장 정답 선택`. 현장 정답 문제는 답변 중에도 진행자가 실제 정답을 선택하고, 마감 없이 공개·채점을 한 번에 할 수 있어 밸런스게임에도 사용 가능
- 현장 화면 QR 참가, 팀 대표가 이름을 입력하면 자동 등록, 팀 수 제한 없음, 답안 수정·재접속
- 진행자 화면에서 5분짜리 일회용 대표 기기 이전 QR 발급. 새 기기 연결 시 기존 세션만 해제하고 팀·답안·누적 점수 유지
- 현장·진행·참가 화면은 Supabase Realtime의 변경 신호로 즉시 다시 조회. 연결 실패 시 0.75~1초 간격 조회, 연결 중에는 10초 안전 조회. 행사 준비 목록은 3초 간격 갱신
- 진행자가 팀 이름·라운드·문제를 수정하거나 삭제 가능. 답안·정답 집계 기록이 있는 팀과 진행 기록에 사용된 문제는 삭제 차단
- 문제 시작 → 답변 중 정답 선택 → 정답 공개·채점 확정 한 번에 → 다음 문제. 라운드 마지막에는 정답을 확인한 뒤 중간 순위 공개. 필요하면 답변만 마감하거나 일시정지/재개 가능
- 객관식·O/X 자동 채점, 주관식 일치 답안 자동 채점과 진행자 판정, 정답은 1점·오답은 0점
- 문제별로 정답 팀 모두 집계 또는 첫 정답 제출 팀만 집계 선택. 오답을 먼저 낸 팀이 있어도 가장 먼저 정답을 제출한 팀에 1점을 부여하며, 채점 정정 시 선착순 집계도 다시 계산
- 문제별 전원 제출 대기 선택. 문제 시작 당시 등록된 팀 모두가 제출해야 답변 마감이 가능하며 시간 제한은 적용하지 않음. 진행자가 마감·정답 공개를 직접 진행
- 진행 중 점수는 진행자에게만 표시하고, 라운드 마지막 문제 정답 공개 후 진행자가 중간 순위 버튼으로 누적 순위 공개
- 점수 정정과 이력, 연습 문제, 리허설 모드와 초기화, 결과 JSON 다운로드
- 동점 공동 순위, 문제 무효 처리, 서버 기준 마감 시간, 공개 전 정답 숨김

## 로컬 실행

Node.js 22 이상을 권장합니다.

```bash
cd umc-night
npm ci
cp .env.example .env.local
npm run dev
```

`DATABASE_URL`, `DATABASE_PASSWORD`, `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`에 본인 Supabase 프로젝트 값을 넣어야 데이터 기능이 동작합니다. `DATABASE_URL`은 Supabase Postgres **Session pooler** 연결 문자열(포트 5432)에서 비밀번호 부분을 뺀 값이며, `DATABASE_PASSWORD`는 프로젝트 생성 때 정한 비밀번호를 그대로 넣습니다. 환경변수에는 `NEXT_PUBLIC_` 접두어를 붙이지 않습니다. 실시간 연결에 필요한 프로젝트 URL과 공개용 키만 `/api/live`를 통해 브라우저에 제공하며, DB 연결 정보와 서비스 비밀 키는 서버에만 보관합니다. `.env.local`은 커밋하지 않습니다.

1. Supabase 무료 프로젝트를 생성하고 SQL Editor에서 `supabase/migrations/202610140001_init.sql`, `supabase/migrations/202610150001_qr_join.sql`, `supabase/migrations/202610150002_team_transfer.sql`, `supabase/migrations/202610160001_question_rules.sql`, `supabase/migrations/202610190001_live_answers.sql`, `supabase/migrations/202610200001_correct_counts.sql`, `supabase/migrations/202610230001_typing_relay.sql`, `supabase/migrations/202610230002_live_sync.sql` 순서로 실행합니다. `quiz-media` 비공개 Storage 버킷도 생성됩니다.
2. Supabase Authentication에서 진행자 계정을 만듭니다. 해당 사용자의 UUID를 확인하고 SQL Editor에서 `insert into public.host_users(user_id) values ('사용자-UUID');`를 실행합니다.
   - 아이디로 로그인할 계정은 Supabase Auth에 `아이디@umc-night.invalid` 형식으로 등록하고 이메일을 자동 확인 처리합니다. 아이디는 영문·숫자·밑줄 3~32자이며 소문자로 저장합니다. `/admin`에서는 아이디만 입력할 수 있고, 기존 이메일 계정도 그대로 로그인할 수 있습니다. 이 별칭 주소로는 메일을 받을 수 없으므로 비밀번호 재설정은 Supabase 관리자가 처리합니다. 비밀번호는 코드나 문서에 저장하지 않습니다.
3. `npm run dev`로 실행한 뒤 `/admin`에서 로그인합니다. `/screen`의 QR을 띄우면 팀 대표가 `/join`으로 접속해 이름을 입력하고 자동 등록합니다. 한 팀당 대표 기기 하나를 사용하며, 같은 이름은 중복 등록할 수 없습니다.
4. 라운드와 문제를 등록하고 `/admin/live`에서 연습 게임을 만든 뒤 `/join`, `/play`, `/screen`을 각각 확인합니다.
5. 대표 휴대폰을 바꿔야 하면 진행자 노트북의 `/admin/live`에서 해당 팀의 `기기 이전 QR`을 발급하고 새 휴대폰으로 스캔합니다. 새 기기에서 `이 기기로 이어하기`를 누르면 기존 대표 기기의 접속이 해제됩니다. 다시 발급한 QR은 이전 QR을 무효화합니다.

개발 시 `npm run typecheck`, `npm run build`, `npm test`를 실행합니다. 실제 DB 흐름 통합 테스트는 **비어 있는 별도 테스트 DB**에 마이그레이션을 적용한 후 `TEST_DATABASE_URL=postgresql://... npm test`로 실행합니다. 테스트는 기존 팀 데이터가 있으면 중단합니다.

## Vercel 배포

Vercel에 이 저장소를 연결하고 **Root Directory를 `umc-night`**로 설정합니다. 프레임워크는 Next.js를 선택합니다. `.env.example`의 5개 변수를 Vercel 프로젝트의 Environment Variables에 추가하고 배포합니다. 프로덕션 빌드에서는 QR 참가·기기 이전·문제 규칙·현장 정답·점수·타자 릴레이·실시간 신호 마이그레이션이 먼저 적용되며, 적용에 실패하면 빌드도 실패합니다. 로컬·미리보기 빌드에서는 이 자동 마이그레이션을 건너뜁니다. 기본 `*.vercel.app` 주소를 사용하면 별도 도메인 비용이 필요 없습니다. Supabase 무료 플랜과 Vercel Hobby 사용량·약관이 행사 용도와 계정 상황에 맞는지 배포 전에 확인하세요. 이 저장소에는 실제 Supabase 프로젝트나 Vercel 프로젝트 연결 정보가 포함되지 않습니다.

10월 23일까지 실제 배포 주소에서 팀 대표 기기들과 진행자 노트북, 16:9 대형 화면으로 전체 리허설을 끝내는 것을 목표로 합니다. 행사 당일에는 노트북 화면을 **확장**하고 `/admin/live`는 노트북에, `/screen`은 프로젝터에 띄웁니다. 인터넷이 끊기면 문제 진행을 멈추고 답안을 종이에 적어 둔 뒤 연결 복구 후 재개하세요. 네트워크 없이 자동으로 답안이 동기화되지는 않습니다.

## 권한과 데이터

브라우저는 정답·답안·점수 DB 테이블에 직접 접근하지 않습니다. 실시간 연결은 내용이 없는 변경 신호 테이블(`game_events`: UUID·생성 시각)만 읽을 수 있습니다. 서버가 Supabase Auth와 팀 쿠키를 확인한 뒤 PostgreSQL에 접근합니다. 정답과 이미지 공개 시점은 서버 응답으로 제어합니다. 답안·채점·점수는 DB에 저장되어 새로고침 후에도 유지됩니다. 실제 행사 기록은 UI에서 초기화할 수 없고, 연습 모드의 최근 실행만 초기화할 수 있습니다.

디자인 자산의 출처와 사용 조건은 [ASSETS.md](docs/ASSETS.md)를 확인하세요. 세부 요구사항과 계획은 [IMPLEMENTATION_PLAN.md](IMPLEMENTATION_PLAN.md)에 기록되어 있습니다.

## 타자 릴레이 운영

1. `/admin/setup`에서 유형을 **타자 릴레이**로 선택하고 게임 제목·공통 차례 수·차례별 문장을 저장합니다. 기본 5차례이며 1~10차례로 바꿀 수 있습니다. `첫 문장을 전체 차례에 적용`으로 같은 문장을 반복할 수 있습니다. 모든 팀에 같은 문장 순서를 적용합니다.
2. `/admin/live`에서 해당 문제를 열면 등록된 팀 목록과 문장 설정을 고정합니다. 첫 문장은 미리 보이지만 입력·제출은 시작 전 차단합니다. 각 팀의 `/play`에서 **준비 완료**를 누릅니다.
3. 전 팀 준비를 확인하고 **전 팀 동시 시작**을 누르면 5초 뒤 공통 서버 시각에 입력을 시작합니다. 한 사람이 정확히 제출하면 다음 차례로 자동 전환됩니다. 실제 교대는 현장에서 확인하며, 휴대폰 전달 시간도 포함됩니다.
4. 오타로 제출할 때마다 +1초를 누적합니다. 입력을 유지하고 같은 사람이 정확히 고쳐 재제출해야 다음 차례가 됩니다. 수정 중에도 시간은 계속 흐릅니다. 앞뒤 공백·한글 유니코드 표현 차이는 정규화하지만 문장 중간 띄어쓰기·대소문자·문장부호는 일치해야 합니다.
5. 마지막 정답 요청이 API에 도착한 시각을 DB 시간대로 변환해 기록을 고정합니다. 인증·서버 대기·처리 시간은 기록에서 제외합니다. **공식 기록 = 실제 시간 - 진행자 일시정지 시간 + 오타 제출 횟수 × 1초**이며, 0.01초 단위 공동 순위를 사용합니다. 통신 지연도 포함하므로 같은 현장 와이파이에서 실제 기기로 리허설합니다.
6. 전 팀 완료 후 **전 팀 완료 · 결과 공개**를 누릅니다. 강제 마감은 사유를 저장하고 미완료 팀을 DNF로 표시합니다. `우승팀 누적 점수 +1점`을 선택했다면 공동 우승팀도 모두 집계하며, 연습 문제는 집계하지 않습니다.

새로고침하면 차례·벌칙·완료 기록을 서버에서 복구합니다. 미제출 입력과 재시도 요청은 가능하면 현재 탭의 임시 저장소에 보관합니다. 연결이 끊겨도 공식 시간은 흐르며, 광범위한 장애는 진행자가 일시정지하거나 무효 처리합니다. 타자 기록은 수동 정정하지 않으며, 재경기는 새 문제로 등록합니다.

브라우저의 작은 화면으로 배치 검증은 가능하지만 한글 조합·자동 교정·키보드 높이는 실제 iOS Safari와 Android Chrome에서 최종 확인해야 합니다.

## 실시간 진행과 시간 동기화

- 함수 실행 지역은 `vercel.json`의 서울 `icn1`로 지정해 서울 DB와의 왕복을 줄입니다. 진행자 인증은 Supabase의 서명 검증된 JWT claims와 매 요청의 관리자 DB 권한 확인을 사용합니다.
- 공개·채점은 한 트랜잭션이며 버튼 재전송으로 중복 득점하지 않습니다. `전원 제출` 설정은 이 빠른 공개에서도 유지됩니다. 주관식은 선택한 정답과 NFC 정규화·앞뒤 공백 제거·대소문자 무시로 비교하고, 진행자가 사전 체크나 사후 정정으로 유사 답안을 인정할 수 있습니다.
- 변경 신호는 DB 트리거가 커밋한 뒤 전송합니다. 공개 전 문제 정답·다른 팀 답안은 신호에 담지 않으며, 각 화면은 자기 권한의 상태 API를 다시 조회합니다. 진행자는 액션 응답에 포함된 최신 상태를 바로 반영하므로 추가 조회를 기다리지 않습니다. 같은 노트북의 다른 탭은 BroadcastChannel로도 즉시 갱신합니다.
- `/api/clock`에서 DB 시각을 기준으로 요청 수신·응답 송신 시각과 DB 왕복 오차를 제공합니다. 클라이언트는 서버 처리 시간을 뺀 4개 시각 교환으로 보정하며, 초기 3회 중 오차가 작은 표본을 사용하고 15초마다 재보정합니다. 이후 흐르는 시간은 `performance.now()` 기준이라 휴대폰의 날짜/시간 설정 변경이나 느린 API 때문에 흔들리지 않습니다. 모든 타이머가 이 시계를 공유하며, 컴포넌트마다 별도로 시계를 보정하지 않습니다.
- 실제 통신의 비대칭 지연과 기기의 렌더링 지연을 0으로 만들 수는 없습니다. 진행자 화면에 보정 오차 추정치를 표시하며, 공식 판정·순위는 기기 표시값 대신 서버 기록으로 결정합니다. 같은 현장 네트워크에서 실제 휴대폰으로 시작·정지·재접속을 리허설합니다.
